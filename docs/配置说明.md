# rok-assistant 配置说明

这份说明是给**不写程序的人**看的。全程只用鼠标点，不需要打开配置文件、不需要
敲命令。按顺序走一遍大概 10 分钟。

卡在哪一步了，直接跳到对应的那一节。**连不上模拟器是最常见的卡点**，见第 2 步。

---

## 开始之前

先确认这四件事，缺一件后面都会失败：

1. **MuMu 模拟器已经装好**，并且**已经启动**（绿色包里不含模拟器）
2. **游戏已经打开**，人物**站在主城界面**（不是登录页、不是战斗里）
3. 游戏分辨率是 **1920×1080**，界面语言是**中文**
4. 程序解压在**英文路径**下，比如 `D:\rok-assistant\`

> 分辨率和语言不能改：识别用的模板图和检测模型都是按 1920×1080 中文界面采集的，
> 换成别的分辨率或英文界面会认不准、点错地方。

---

## 第 1 步：启动程序

双击 `rok-assistant.exe`。

第一次启动会自动做两件事：

- 在同目录生成 `config.yaml`（你的配置，以后就改它）
- 试着自动找到 MuMu 和 adb 的安装位置填进去

看到标题栏写着「rok-assistant」就是起来了。**看不到窗口**就去 `logs\startup_crash.log`
看错误内容。

---

## 第 2 步：连接模拟器（最容易卡住的一步）

点界面上的 **「⚙ 配置」** 按钮，然后：

1. **左侧列表**里选中一台模拟器（第一次用就只有一台，叫「模拟器0」）

2. 确认「接入方式」是 **「按模拟器选择」**（默认就是，不用动）

3. 看 **「选择模拟器」** 那个列表——**打开配置窗口时程序已经自动扫过一次**了，
   里面会列出 MuMu 里所有的模拟器，**按名字显示**，比如：

   ```
   ● 如愿 · 运行中
   ○ 如愿-2 · 未启动
   ```

   - `●` 和「运行中」= 这台开着，可以用
   - `○` 和「未启动」= 这台没开，先在 MuMu 里把它启动

   列表是空的、或者显示一行带括号的提示，就点下面的 **「扫描模拟器」**
   按钮重扫一次。

4. **选中你正在用的那一台**（选「运行中」的）

5. 点 **「测试连接」**

6. 看到下面这行才算成功：

   ```
   ● 已连接，截图 1920x1080
   ```

   并且下面会出现一张游戏画面的小截图。**看一眼那张图，确认是你这台模拟器现在
   的画面**——如果显示的是别的账号或者黑屏，说明选错了模拟器。

### 连不上模拟器怎么办

**列表里那台显示「○ 未启动」**
在 MuMu 里把那个模拟器启动起来、进到游戏主城，然后回来点「扫描模拟器」重新扫。

**点「测试连接」提示「模拟器「xxx」没有启动，请先在 MuMu 里启动它」**
同上——MuMu 里那台确实没开，或者刚重启过还没进系统。启动它再试。

**点「扫描模拟器」提示「无法运行 MuMuManager」**
程序没找到 MuMu 装在哪。回左侧点 **「全局设置」**，点
**「自动检测 MuMu/adb 路径」**。还不行就手动指定两个文件：

- **MuMuManager.exe** —— 在 MuMu 安装目录下的 `nx_main\` 里
  （老版本 MuMu 可能在 `shell\` 里）
- **adb.exe** —— 和 MuMuManager.exe 在同一个目录（`nx_main\`）

填完回到模拟器页，重新「扫描模拟器」。

**提示「截图 1280x720」而不是 1920x1080**
模拟器分辨率不对。在 MuMu 的「设置 → 显示」里把分辨率改成 **1920×1080**，
重启模拟器后再测。

**提示「连接失败」+ 一行英文**
把整段话截图发给开发者。这通常是环境问题，不是配置写错了。

---

## 第 3 步：配置角色

模拟器连上之后，配置角色。**每个模拟器下面挂一组角色**：

- **车头** —— 负责发起集结的那个人
- **成员** —— 负责去填车头集结的人
- **车头或成员** —— 两种都可能，程序自己判断

### 添加角色

1. 在模拟器页点 **「＋ 添加角色」**

2. **角色名**必须**和游戏里显示的完全一样**（包括标点、空格）

   程序靠识别游戏画面里的名字来确认切到了正确的角色，差一个字就会失败。

3. **分工**选「车头」/「成员」/「车头或成员」

4. **目标城寨等级**：勾 1–10 之间的等级，**最多勾 3 个**

   **勾选的先后顺序 = 搜索顺序**。比如先点 6、再点 4、再点 5，程序就按
   6 → 4 → 5 的顺序去找。想改顺序就取消重勾（新勾的排在最后）。
   下面那行「搜索顺序：6 → 4 → 5」就是给你确认用的。

5. **行军预设**：游戏里「组建部队」弹窗上的预设槽位编号，1–5

6. **兵种**：步兵 / 骑兵 / 弓兵，可多选

7. **填兵目标**（只有「成员」和「车头或成员」要填）：
   在左边列表里选中车头的名字，点 `→` 移到右边。
   这就是「我要去填谁的车」。

8. 点「确定」

### 两条硬规则

**整个配置里至少要有一个车头（或车头或成员）**，否则保存会被拒绝——
成员的活是填车头的集结，没有车头就没得填。

**「成员」和「车头或成员」必须填「填兵目标」**，而且不能填自己。

所以：如果只有一个模拟器、一个账号，把它的分工设成 **「车头」**——
车头不需要填兵目标，能单独跑。想让它也能去填别人的车，就再加一个账号设成
「成员」，或者开第二个模拟器。

---

## 第 4 步：保存并启动

1. 配置窗口右下角点 **「保存」**

   如果弹出「校验失败」，说明有必填项没填。弹窗里会写清楚是**哪一台模拟器的
   哪个角色**的哪个字段有问题，按提示改完再保存。

2. 关掉配置窗口，回主界面点 **「Start」**

3. 主界面上每个角色会出现一张卡片，显示角色名和当前在做什么（中文）

## 附：每个配置项是什么意思

下面这张表是给想手动改 `config.yaml` 的人看的。**用界面改的话可以跳过**——
界面上每一项都有对应的控件。

### 全局设置

| 配置项 | 中文名 | 说明 |
|---|---|---|
| `screen_width` / `screen_height` | 截图宽 / 高 | 必须是 1920 / 1080，**不要改** |
| `locale` | 界面语言 | 必须是 `zh-CN`，**不要改** |
| `mumu_manager_path` | MuMuManager 路径 | MuMu 安装目录下的 `MuMuManager.exe`，点「自动检测」能自动填 |
| `adb_path` | adb 路径 | MuMu 安装目录下的 `adb.exe`，点「自动检测」能自动填 |
| `yolo_model` | 检测模型 | `models/detect.onnx`，**不要改** |
| `ocr_name_fallback` | OCR 认名字兜底 | 默认 `true`。车头名字优先用模板认，没匹配上时改用文字识别认。**关掉它，配置里点名但 manifest 没有模板的车头就没有任何判据**（会打 warning 并整轮空转）。独立开关，与有没有配 `yolo_model` 无关 |
| `max_rounds` | 最大轮数 | 每个角色做完多少轮（开集结 + 填兵 + 回城）自动收工，默认 10 |
| `max_consecutive_failures` | 连续失败上限 | 连续失败这么多轮就自动停，默认 3。体力用完时会触发 |
| `anti_detection` | 防检测参数 | 下面单独一张表 |

> `log_dir` / `template_dir` 是程序内部用的路径，一般不用改。

### 防检测参数

目的是让点击的坐标和节奏不总是完全一样，看起来不像脚本。
**默认值就能用，不建议改。**

| 配置项 | 中文名 | 说明 |
|---|---|---|
| `click_offset_px` | 点击偏移 | 每次点击的坐标在 ±N 像素内随机，默认 8 |
| `action_delay_min` / `action_delay_max` | 动作延迟 | 每次点击前随机等待的秒数范围，默认 0.1–0.5 |
| `state_delay_min` / `state_delay_max` | 状态延迟 | **当前不生效**（保留字段，改了不影响行为） |
| `jitter_ratio` | 抖动比例 | **当前不生效**（保留字段，改了不影响行为） |
| `debug_no_jitter` | 调试模式 | 改 `true` 会关掉全部随机化。**只在排查问题时用**，平时保持 `false` |

连点段间隔（`rapid_click_min` / `rapid_click_max`）管的是「同一个按钮上连着点好几下」的节奏，
比如调等级时连着点 `+` / `-`。它和「每次动作前的延迟」（`action_delay_min` / `action_delay_max`）
是两回事——后者管的是两次不同动作之间的等待，连点段则是同一控件内部那几下之间的间隔。
连点段的下限别调太低，否则游戏会丢点击。

### 模拟器（`instances` 这一段）

配置里 `instances:` 下面每一条就是一台模拟器。

| 配置项 | 中文名 | 说明 |
|---|---|---|
| `id` | 内部标识 | 自动生成（`mumu0`、`mumu1`…），**不用改**。跨模拟器填兵时靠它引用 |
| `name` | 显示名 | 随便起，只是给你自己在界面上认机器用 |
| `mumu_index` | 模拟器编号 | 对应 MuMu 里的哪一台。**在界面上按名字选，不用手填** |
| `adb_address` | adb 地址 | 只有在「手动填 adb 地址」模式下才用（非 MuMu 的模拟器走这条） |
| `window_title_pattern` | 窗口标题 | 只有用窗口截图模式时才需要，一般留空 |
| `characters` | 角色列表 | 这台模拟器上要跑的角色，见下 |

> `mumu_index` 和 `adb_address` **必须二选一**：两个都不填会被拒绝，两个都填也会
> 被拒绝。用界面的「接入方式」下拉切换，别手动两个都写。

### 角色（`characters` 这一段）

| 配置项 | 中文名 | 说明 |
|---|---|---|
| `id` | 内部标识 | 自动生成（`char-xxxxxxxx`），**不用改** |
| `name` | 角色名 | **必须和游戏内显示名完全一致**（OCR 认名字用） |
| `role` | 分工 | `leader`=车头 / `member`=成员 / `either`=车头或成员 |
| `target_levels` | 目标城寨等级 | 最多 3 个，1–10 不重复。**列表顺序就是搜索顺序**（如 `[6, 4, 5]`）。成员角色这项不影响行为，但必填 |
| `march_preset` | 行军预设 | 组建部队弹窗上的预设槽位，1–5 |
| `march_troop_types` | 兵种 | 可选 `infantry`（步兵）/ `cavalry`（骑兵）/ `archer`（弓兵），可多选 |
| `fill_target_leaders` | 填兵目标 | **成员和「车头或成员」必填**，车头不能填。每条写 `{ instance: 车头的id, name: 车头角色名 }` |

## 常见问题

**程序启动一闪而过 / 没窗口**
看 `logs\startup_crash.log`。

**主界面没有角色卡片**
配置里没读到角色，或格式不对。点「刷新配置」看提示。
手动改过 `config.yaml` 的话注意：YAML 只能用空格缩进，**不能用 Tab**。

**点「保存」提示校验失败**
弹窗里会写是哪台模拟器的哪个角色的哪个字段。按提示补上必填项。
常见的两个：成员没填「填兵目标」、模拟器既没选也没填 adb 地址。

**角色卡片一直显示「出错，重试中」**
多半是游戏没停在主城界面，或者分辨率/语言不对。回到游戏里确认一下。

**跑着跑着停了**
看是不是 `max_rounds`（轮数做完自动收工）或 `max_consecutive_failures`
（连续失败自动停，常见原因是行动力用完）。改大这两个值，或给游戏补行动力。

**模拟器重启后要重新配置吗**
不用。程序会自动重新连接。如果还是不行，在配置里点一次「测试连接」。

---

## 还想更省事？

- **一个模拟器只跑一个账号**：配一个角色、分工选「车头」就够（车头不需要
  填兵目标，能单独跑）
- **多个模拟器一起跑**：每个模拟器加一条 `instances`，各自配角色；
  成员可以在「填兵目标」里选**别的模拟器**上的车头
- **先确认认不认得界面**：主界面点 Start 后看卡片上的状态文字，
  卡在哪一步日志里都有中文说明（`logs\` 目录下）
