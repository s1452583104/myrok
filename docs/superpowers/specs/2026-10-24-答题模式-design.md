# 答题模式（quiz mode）设计

**日期**：2026-10-24
**状态**：已与仓库主人确认方向（题库 + AI 兜底 + 答后学习；自动导航；答到活动结束算一轮；
答不出时随机选一个靠学习补正）
**参考实现**：`dati/ROK答题助手与题库/rok-quiz-helper/`（第三方离线脚本，仅作算法参考，不随包分发）

---

## 1. 目标与非目标

**目标**：以模拟器为单位，自动进入《万国觉醒》知识问答活动，识别题干与四个选项，
用「本地题库 → 大模型兜底 → 随机」三级策略作答，答完从画面的绿色高亮反推正确答案
并写回本地题库，一直答到活动结束，冷却后进入下一轮。

**非目标（本轮明确不做）**：

- 「求助」「跳过」按钮——活动不一定提供，入口位置也未知。
- 跨角色/跨模拟器共享学习结果——本轮学习结果按机器落盘。
- 题库联网同步、题库编辑界面。
- 把题目截图当图像识别——题干与选项一律走 OCR 文本。
- 活动入口的多路径导航（例如不同活动周期入口不同）——只做一条确认过的路径。

---

## 2. 架构

沿用现有分层，`core/quiz/` 是纯逻辑包（不 import Qt、不 import workers），
状态机只做「取帧 → 调纯函数 → 决定下一步」。

```
core/quiz/          bank.py  screen.py  verify.py  solver.py  llm.py
workers/            quiz_sm.py
coordination/       quiz_runtime.py   (QuizCoordinator extends BaseCoordinator)
infra/config.py     QuizConfig / QuizLLMConfig
templates/quiz/     quiz_bank.json    (随包只读题库)
gui/                IMPLEMENTED_MODES 加 QUIZ；配置界面答题页放开
tools/              quiz_acceptance.py  (素材验收，不参与 pytest)
```

**为什么不照搬 `dati` 的 `QuizApp`**：那是一个自带 `while True` 的主循环与自己的 ADB 封装，
绕开了本项目的 `BaseCoordinator` / `WorkerRunner`（没有冷却重建、没有状态发布、
GUI 接不上），并且会引入第二套 ADB 调用路径。这里只搬它的**算法**
（几何还原、三级匹配、绿色判定），不搬它的进程模型。

---

## 3. 数据流

```
capture() ──► RapidOcrEngine.detect_text(frame) ──► [(BBox, text, conf), ...]
                                                    │
                                    screen.parse_question()
                                                    ▼
                                  ScreenQuestion(text, options{A..D: (text,bbox)})
                                                    │
                          solver.answer()  bank.exact → bank.fuzzy → llm → random
                                                    ▼
                                       Decision(letter, text, source)
                                                    │
                                          click(option.center)
                                                    ▼
                              sleep(verify_delay) → capture() → verify.pick_correct_option()
                                                    │
                                          bank.learn(question, correct_answer)
```

**复用点**：`RapidOcrEngine` 已经返回带 bbox 的文本块，且带单帧缓存——
答题模式不需要再引入 RapidOCR 或 PaddleOCR。

## 4. 组件规格

### 4.1 `core/quiz/screen.py` — 从文本块还原题目

纯函数，输入 OCR 文本块（沿用项目自己的 `BBox`：`x1/y1/x2/y2` + `center()`），
输出 `ScreenQuestion | None`。**分辨率无关**：全部判据用相对位置与块间关系，
不出现任何绝对坐标（素材实测有 2664×1200 与 1280×576 两种尺寸，都不是 1080p）。

算法按下面这个**有序**规则走（比参考实现严格，因为素材里暴露了它的漏洞）：

1. **题干**：以题号块（`Q1`/`Q2`…）为锚点，取同一行右侧的长块；续行按
   「上一行底边 +0.5~1.5 倍行高」合并。没有题号块时退化为「含问号的最长块」。
   题干底边记为 `q_bottom`。
2. **候选过滤**：丢掉噪声词块（`放弃/求助/确定/开始/继续/退出/返回/关闭/分享`）、
   含动态词（`剩余时间/答题时间/倒计时/通过后可获/暂入/已答/积分/排名/宝石/关卡/
   观看/复活/求助`）的块、纯数字块、孤立字母块、题号块、以及位于 `q_bottom` 以上的块。
3. **分列轴 = 画面中线**（`frame_width / 2`）。**跨轴的块直接扔掉**——2×2 选项
   永远分居轴两侧，而提示语（`您一共拥有3次求助的机会…`）、复活 toast、HUD 长行
   都会横跨轴。这一条替代参考实现「池子不干净就取前 4 个」的将就做法
   （实测会把提示语挤进选项）。
   **不要用题干中心当轴**：短题干（`统帅贝利撒留的昵称是？`）的中心偏左，
   会落进左列选项的 x 区间里，把真选项判成跨轴——9 份素材里 4 份会因此解析失败。
4. **分行**：剩下按 y 聚类，容差 = 块高中位数 × 0.6。**丢掉只有 1 个成员的行**
   （倒计时、`剩余人数` 这类 HUD 都是孤立行）。
5. **验收**：必须剩下**恰好 2 行、每行恰好 1 左 1 右**，四块两两不重叠，
   否则返回 `None`（状态机重拍，重拍还不行就中止本轮）。
6. **指派**：上行左 A、上行右 B、下行左 C、下行右 D。

- 文本线索（块文本以 `A/B/C/D` + 分隔符开头）仍保留：命中时以字母为准，
  几何只用来补齐缺失字母，避免整体错位。
- **宁可不点，不要点错**：解析不出 4 个选项就返回 `None`。
- 标题关键词（`国士无双`/`国王无双`/`习题演练`/`知识问答`/`复试`/`初试`）用于
  `detect_quiz()` 判定当前是否在答题界面。素材实测：复试页标题是
  `国士无双-复试`（OCR 有时读成 `·`），习题演练页标题是顶部左对齐的 `习题演练`。

### 4.2 `core/quiz/bank.py` — 题库

**数据形式**：与参考实现**兼容**的 JSON 数组，每项 `{"no", "q", "a", "source"}`。
兼容的目的是让仓库主人能直接用现成题库文件或手动编辑。

**归一化**：NFKC 全角转半角 → 去标点/空白/装饰符 → 去 `Q\d` 题号前缀 → 小写。
**数字必须保留**——`24小时` 与 `48小时` 不能归一成同一个值。

**匹配**：

- 精确：归一化后相等。
- 模糊：`difflib.SequenceMatcher` 相似度；互含子串时按长度比打折加权；阈值
  `fuzzy_threshold`（默认 0.72，可配）。
- 答案落到选项：把题库答案文本与四个选项文本比相似度，取最高且 ≥ 0.6。

**两个题库文件**：

| 文件 | 位置 | 权限 | 作用 |
|---|---|---|---|
| 随包题库 | `resource_dir()/templates/quiz/quiz_bank.json` | 只读 | 权威条目（1076 条，来自 `dati`） |
| 学习结果 | `user_dir()/quiz/learned.json` | 可写 | 运行时新增/修正 |

**合并规则**：

- 随包条目**权威**：同题（归一化后相等）以随包答案为准，学习结果不得覆盖。
  这条防止一次颜色误判污染权威答案。
- 学习条目之间可以互相修正（后学覆盖先学）。
- 写入用「临时文件 + `os.replace`」，崩溃不丢题、不产生半截文件。

### 4.3 `core/quiz/verify.py` — 绿色高亮 = 正确答案

答完后正确选项显示绿色；答错时所选项显示红色、正确项仍是绿色——所以**答对答错都能学到**。

实现用 `cv2`（项目已有）而不是 PIL：对每个选项 bbox 缩采样后转 HSV，统计绿/红像素占比。

**色相刻度必须换算**：参考实现用 PIL 的 HSV（H∈[0,255]，绿≈85），
`cv2.cvtColor(..., COLOR_BGR2HSV)` 的 H 是 **[0,179]**——直接把 60/110 抄过来
会落到青色区间，一行绿都数不出来。等价值：

| 颜色 | PIL（0-255） | cv2（0-179） |
|---|---|---|
| 绿 | 60 ~ 110 | **42 ~ 77** |
| 红 | ≤15 或 ≥245 | **≤11 或 ≥172** |

先在 RGB/BGR 空间缩采样再转 HSV（直接缩 HSV 会因插值产生伪色相），
并要求 `S ≥ 40`、`V ≥ 40`（PIL 的 0-255 刻度；cv2 的 S/V 也是 0-255，同值可用）。
判据：`绿占比 ≥ min_green_ratio`（**默认 0.55**）且 `绿 > 红`。
默认值来自素材实测：正确选项实测 0.97 / 0.98 / 1.00，而唯一的非选项绿色块（`日程`
标签）只有 0.35–0.36——0.55 在两者之间，留了两倍余量。参考实现的 0.35 太贴噪声底。
没有明显绿色 → 返回 `None`，**不学习**（不猜）。

### 4.4 `core/quiz/llm.py` — 大模型兜底

- OpenAI 兼容 `POST {base_url}/chat/completions`，用标准库 `urllib.request`，
  **不新增依赖**。
- 提示词要求只回一个字母；回答做严格校验（必须是 A/B/C/D 且在本次选项里），否则当失败。
- **任何失败（超时、断网、4xx/5xx、响应格式异常）都返回 `None`**，绝不抛异常，
  也不重试；失败后直接进入随机兜底。一次失败只影响一题，不值得为它拖慢整轮。
- `enabled=false` 时完全不发网络请求。

### 4.5 `core/quiz/solver.py` — 三级决策

```
题库（精确 → 模糊） → LLM（可关） → 随机
```

- 返回 `Decision(letter, text, source ∈ bank|llm|random)`。
- 随机源可注入（`rng`），单测固定种子。
- 三条路径**都会点击**——随机是仓库主人确认的兜底策略（宁可错一题、靠学习补正，
  也不要卡住整轮）。

### 4.6 `workers/quiz_sm.py` — 状态机

```
NORMALIZE ──► OPEN_QUIZ ──► READ ──► ANSWER ──► VERIFY ──► LEARN ─┐
                   ▲                                                │
                   │                                    ADVANCE ◄───┘
                   │                                       │
                   └────────── 还有题（回到 READ） ◄────────┤
                                                           └─ 活动结束/达上限 ─► COOLDOWN ─► END
```

- **READ**：重新截屏 + OCR + 解析，**最多尝试 `parse_retries` 次**（每次间隔一拍）。
  - 解析成功 → `ANSWER`。
  - `detect_quiz()` 为假且本轮**还没答过题** → `quiz_screen_lost` 中止：刚点进去的
    界面被弹窗或别的页面顶掉了。
  - `detect_quiz()` 为假且本轮**已答过题** → 正常收工（活动结束），进 `COOLDOWN`。
  - `detect_quiz()` 为真但几次都解析不出 4 个选项 → `quiz_parse_failed` 中止：
    界面还在但这一帧读不干净，宁可换一轮也不要乱点。
- **ANSWER**：`auto_click=false` 时只记日志不点击（半自动，用于首次真机验证）。
- **VERIFY**：睡 `verify_delay` 秒再截屏；找不到绿色 → 跳过学习继续。
- **LEARN**：把**绿色选项的文本**（不是我们点的那个）写进题库。
- **ADVANCE**：画面仍能解析出题目且题干与上一题**不同** → 回 `READ`；
  相同 → 视作结果画面未翻页，睡一拍再判（有上限）；题目消失 → 本轮结束。
- **COOLDOWN**：睡 `round_cooldown_min` 分钟后走 END；runner 重建 SM 开下一轮。
  这样活动没开时大约每「冷却 + 一轮耗时」重试一次，不会 30 秒一次空转。

所有失败写成 `ctx["fail_reason"] = <常量>` 并走到 END 边，**绝不抛异常**。

### 4.7 `coordination/quiz_runtime.py` — `QuizCoordinator`

`BaseCoordinator` 的子类，覆写：

- `_instances()` → `config.instances_for(AppMode.QUIZ)`（`RootConfig.instances_for`
  已存在，宝石在用，按模式分派）
- `_sm_factory_for(char, handle, recognizers, profile)` → `create_quiz_state_machine(...)`
- `_max_rounds()` → `config.quiz.max_rounds`
- `_pre_start()` → 加载题库（**进程级，持在 coordinator 上**，SM 每轮重建不重读）

题库对象与 LLM 客户端都挂在 coordinator 上（与 `ActionLedger` 同理），
SM 每轮重建时只拿引用。

`_route_for` 返回 `None`（答题没有跨实例链路）。

## 5. 配置

`infra/config.py` 新增：

```python
class QuizLLMConfig(BaseModel):
    enabled: bool = False
    base_url: str = "https://api.deepseek.com/v1"
    model: str = "deepseek-chat"
    api_key: str = ""          # 明文落在 config.yaml，配置说明里会写明这一点
    timeout_s: float = Field(default=8.0, gt=0)

class QuizConfig(BaseModel):
    instances: list[QuizInstanceConfig] = Field(default_factory=list)
    max_rounds: int = Field(default=3, ge=1)
    fuzzy_threshold: float = Field(default=0.72, ge=0.0, le=1.0)
    verify_delay: float = Field(default=1.2, ge=0.0)
    min_green_ratio: float = Field(default=0.55, ge=0.0, le=1.0)
    max_questions_per_round: int = Field(default=30, ge=1)
    round_cooldown_min: float = Field(default=10.0, ge=0.0)
    parse_retries: int = Field(default=2, ge=1)      # 同一题最多读几次再放弃
    auto_click: bool = True
    llm: QuizLLMConfig = Field(default_factory=QuizLLMConfig)
```

**注意不要继承 `ModeConfig`**：`ModeConfig`（`infra/config.py:279`）是寨多多专属的
`instances: list[InstanceConfig]`（`min_length=1` + leader/member 交叉校验），
答题套上去会当场加载失败。`QuizConfig` 与 `GemConfig` 一样直接继承 `BaseModel`，
自己写实例 id / 角色 id 的唯一性校验。

**实例与角色模型**：`InstanceBase` 已经是抽好的公共基类（`infra/config.py:219`，
mumu/adb 二选一校验都在里面）。答题和宝石一样「一台模拟器恰好一个号、没有分工」，
所以阶段 1 把宝石那对类改名为中性名并保留别名：

```python
class NoRoleCharacterConfig(BaseModel):     # 原 GemCharacterConfig
    id: str
    name: str = Field(min_length=1)

class NoRoleInstanceConfig(InstanceBase):   # 原 GemInstanceConfig
    characters: list[NoRoleCharacterConfig]  # _one_character 校验照搬

GemCharacterConfig = NoRoleCharacterConfig  # 别名：config.yaml 与现有测试零改动
GemInstanceConfig  = NoRoleInstanceConfig
QuizInstanceConfig = NoRoleInstanceConfig
```

类别名的风险只有一处：pydantic 报错信息里类名会变成 `NoRoleInstanceConfig`。
若有测试断言了字符串 `GemInstanceConfig`，改成断言行为而不是类名——不要为此回退成
两套重复定义。

**校验**：`RootConfig` 里 `quiz: QuizConfig = Field(default_factory=QuizConfig)`；
实例 id / 角色 id 唯一性校验与 gem 同形。

## 6. 错误处理与失败原因

新增常量（`workers/quiz_sm.py`），全部加入 `workers/runner.py` 的 `_ENV_FAIL_REASONS`
（**环境类，不计连续失败**）：

| 常量 | 值 | 含义 |
|---|---|---|
| `QUIZ_ENTRY_MISSING_REASON` | `quiz_entry_missing` | 找不到活动/答题入口按钮 |
| `QUIZ_SCREEN_LOST_REASON` | `quiz_screen_lost` | 答题中画面被弹窗/其他界面顶掉 |
| `QUIZ_PARSE_FAILED_REASON` | `quiz_parse_failed` | 在答题界面但解析不出题干或 4 个选项 |

沿用 `NORMALIZE_STUCK_REASON`。

**LLM 失败不产生失败原因**——它只是让决策降级为随机。

**反例（必须留在名单外）**：点击选项后画面毫无变化且题干不变 → 那是真出问题了，
按普通失败累计。

## 7. 全局约束

- **绝不抛异常**：失败 = `fail_reason` + END 边。`WorkerRunner` 收到 step 异常不重建
  SM，会在同一状态退避重放，攒满 6 次停机。
- **路径不许 CWD 相对**：只读走 `infra/app_paths.resource_dir()`，可写走 `user_dir()`。
- **fork 外部程序一律走 `infra/subproc.py`**（本模式不额外 fork；ADB 走现有 `AdbHandleSource`）。
- **文档只记字段作用，不记取值**——要核对直接读 `config.yaml`。
- 用 `.venv/Scripts/python.exe`；`tools/*.py` 的中文输出配 `-X utf8`。
- `pixel_stats:` 等既有 manifest 约定不改动。
- 随包资源新增 `templates/quiz/quiz_bank.json`；`rok-assistant.spec` 已整体打包
  `templates/`，无需改打包脚本，但需要在 `build_package.REQUIRED_RESOURCES` 里
  加一条产物断言。

## 8. 测试策略

| 层 | 怎么测 |
|---|---|
| `screen` | 合成文本块（含题号、多行题干、噪声块、2×2 与带字母前缀两种排布）→ 断言题干与四个字母的文本/中心点 |
| `bank` | 归一化（全角/标点/题号前缀/数字保留）、精确/模糊、随包权威不被覆盖、学习可互相修正、原子写 |
| `verify` | 合成纯色块（绿/红/灰）→ 断言选中绿色、全灰返回 None |
| `llm` | 注入假的 urlopen：正常/超时/5xx/返回非字母 → 只在前者给字母，其余一律 None |
| `solver` | 三级顺序、随机兜底的确定种子、source 标注 |
| `quiz_sm` | `MockHandleSource` + 假识别器 + 假 OCR 文本块 + 假时钟/睡眠：完整答对一题、答错后学对、解析失败中止、活动结束收工、不抛异常 |
| `QuizCoordinator` | 配置只读 quiz 段、SM 工厂透传、题库进程级只加载一次 |

**整屏 OCR 不进单测**（慢且需模型）；`screen` 的输入一律是合成文本块。
真实素材走 `tools/quiz_acceptance.py`（§11）——它是验收脚本，不是 pytest 用例。

## 9. 阶段划分

| 阶段 | 内容 | 能否离线完成 |
|---|---|---|
| 0 | 入口探针：只剩「地图 → 活动页 → 习题演练」的点击路径没素材（答题页、结果页、绿色判定已由 `dati/test/` 素材覆盖，见 §11） | **必须真机** |
| 1 | 配置层（`QuizConfig` / `QuizLLMConfig` / 实例角色模型）+ 随包题库入库 + 打包断言 | 可以 |
| 2 | `core/quiz/` 五个模块 + 单测 | 可以 |
| 3 | `workers/quiz_sm.py` + 单测 | 可以 |
| 4 | `QuizCoordinator` + `IMPLEMENTED_MODES` + GUI + 配置界面答题页 | 可以 |
| 5 | 真机端到端（先 `auto_click=false` 观察，再放开点击）+ §11 验收全过 | **必须真机** |

**阶段 0 的产出决定阶段 3 的入口状态机**：入口按钮叫什么、要点几步、结果页停留多久。
在拿到真机帧之前，`OPEN_QUIZ` 只能按「OCR 找到活动标题 → 点 `习题演练` 那一行」
写（素材显示活动页里 `习题演练` 是可点的行文本，不必做模板），并在日志里留足痕迹。

## 10. 已知局限

1. **题库覆盖率**：1076 条只覆盖某一时段的活动题库；新题靠 LLM 或随机 + 学习补。
2. **学习依赖颜色判定**：阈值来自 `dati/test/` 的 6 个绿色样本（0.97~1.00），
   跨主题/跨亮度/换号未验；误判会写入错误答案（学习条目可被后续学习修正，
   但需要再遇到同一题）。
3. **随机兜底会故意答错**——这是仓库主人明确选择的策略，代价是浪费活动次数。
4. **入口导航只验到活动页**：素材里的视频都从活动页开始，`地图 → 活动页` 那一步
   仍要真机确认；`OPEN_QUIZ` 的点击目标按「`习题演练` 行文本」写。
5. **API Key 明文**：`config.yaml` 里的 `api_key` 不加密；绿色包用户需自行保管。
6. **LLM 有网络与费用成本**，且会把题目文本发给第三方服务——`enabled=false` 可完全关闭。

### 11.3 判据与执行

`tools/quiz_acceptance.py <素材目录>` 逐条打印 `PASS/FAIL/SKIP`：

1. **parse**：题干文本与四个字母的选项文本与上表逐字相等（OCR 已读错的字不追究，
   比对用同一帧的 OCR 结果）；
2. **decide**：有地面真值的题断言 `source == "bank"` 且字母等于真值；
3. **verify**：对上表绿块字母断言 `pick_correct_option()` 返回同一个字母，
   且 `min_green_ratio=0.55` 下其余选项全被判否；
4. **learn**：用视频帧走 `bank.learn()`，断言 `learned.json` 多出该条，
   且随包题库条目**未被覆盖**。

随机兜底会让字母不确定：验收只断言 `source` 与「有决策且 letter ∈ ABCD」，
不断言具体字母（除非将来加了固定种子开关）。
