# 多模式框架 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把配置按模式分区（`app:` + `zhaiduo`/`gem`/`quiz`），主界面改成「应用头 + 左侧导航 + 每模式一页」，让「寨多多模式」成为三个模式里的第一个，宝石/答题是占位页。

**Architecture:** 模式是**界面概念，不是运行时概念**——`config.yaml` 里没有 `mode` 键，`RuntimeCoordinator` 只跑寨多多，模式唯一进入运行时的入口是 `GuiController.start(mode)`。配置层加 `AppMode` / `ModeConfig` / `ZhaiduoConfig`，`_cross_checks` 跟着数据搬到 `ZhaiduoConfig`。界面层把「开始运行/停止」从顶部操作栏下沉到各模式页头，用一个 `_sync_ui_state()` 从「运行中的模式 / 本页的模式 / 有无角色」三个输入推导全部控件状态。

**Tech Stack:** Python 3.14、pydantic v2、PyQt6、pytest（`.venv/Scripts/python.exe`）。

**Spec:** `docs/superpowers/specs/2026-10-13-多模式框架与城寨等级扩展-design.md`（§4 城寨等级那部分已由 `2026-10-13-城寨等级1-15.md` 实施完毕；本计划只做 §2/§3/§5 的多模式部分）。

## Global Constraints

- **仓库约定：直接在 `main` 上提交**，不建分支。
- **一律用 `.venv/Scripts/python.exe`**，别用系统 `python`（那是 torch+cpu，会静默降级跑 CPU）。
- `tools/*.py` 的中文输出要配 `-X utf8`（控制台是 GBK）。
- **本仓库没有配置 linter / formatter**（无 ruff / flake8 / mypy），别去找 lint 命令。
- **文档只记字段作用，不记取值**——不写「哪个角色配了几级 / 什么预设 / 什么兵种」。
- **`config.example.yaml` 必须与代码同批更新**（spec §5.2 发布顺序硬约束）：否则首启从旧示例生成出来的 `config.yaml` 自己就加载失败，用户连「删掉重来」都救不回来。
- **模式不落盘**：`config.yaml` 里**没有** `mode` 键。模式固定开在寨多多。
- **老配置不迁移**：顶层 `instances:` → `zhaiduo.instances:` 是破坏性变更，硬报错让用户重配。
- **不跑 `tools/calibrate_yolo_threshold.py`**：本计划不改权重、不改模板图。
- **`.pytest_tmp` 是 repo 内的固定 basetemp**：被强杀的 pytest 会留下占住日志文件的孤儿进程，之后每次 pytest 都在 setup 阶段抛 `PermissionError [WinError 32]`，表现为一大片与被测代码无关的 `E`——**极易误判成回归**。修法：杀光孤儿 `python.exe` → `rm -rf .pytest_tmp` → 重跑。
- **不许出现裸 `subprocess.run|Popen`**（`tests/unit/infra/test_subproc.py` 有扫描测试盯着），一律走 `infra/subproc.py`。
- 工作树里若有无关在飞改动，**只 `git add` 本任务改的那几个文件**，不要 `git add -A`。

- [ ] **Step 4: 把 `_cross_checks` 从 `RootConfig` 搬到 `ZhaiduoConfig`**

在 `InstanceConfig` 之后、`AppConfig` 之前插入：

```python
class ModeConfig(BaseModel):
    """一个模式的专属配置。宝石/答题现在是空壳，所以允许空。"""
    instances: list[InstanceConfig] = Field(default_factory=list)


class ZhaiduoConfig(ModeConfig):
    """寨多多模式：唯一实现了的模式，所以它的校验最严。

    **校验跟着数据走，不跟着模式走**：原来挂在 RootConfig 上的 _cross_checks
    整块搬到这里，因为「至少一个 leader/either」「填兵目标互相指向」这些规则
    说的是**角色之间**的关系，而角色只存在于某个模式里。宝石/答题现在没有角色，
    硬套「至少一个 leader」会让它们当场加载失败。
    """
    instances: list[InstanceConfig] = Field(min_length=1)

    @model_validator(mode="after")
    def _cross_checks(self):
        inst_ids = [i.id for i in self.instances]
        if len(inst_ids) != len(set(inst_ids)):
            raise ValueError("实例 id 重复")
        char_ids = [c.id for i in self.instances for c in i.characters]
        if len(char_ids) != len(set(char_ids)):
            raise ValueError("角色 id 重复")
        if not any(c.role in (RoleEnum.LEADER, RoleEnum.EITHER)
                   for i in self.instances for c in i.characters):
            raise ValueError("整个配置至少需要 1 个 leader/either 角色")
        by_key = {(i.id, c.name): c for i in self.instances for c in i.characters}
        for i in self.instances:
            for c in i.characters:
                if c.role == RoleEnum.LEADER and c.fill_target_leaders:
                    raise ValueError(
                        f"Character {c.name}: leader 不能配置 fill_target_leaders")
                if c.role in (RoleEnum.MEMBER, RoleEnum.EITHER):
                    if not c.fill_target_leaders:
                        raise ValueError(
                            f"Character {c.name}: member/either 必须配置 fill_target_leaders")
                    for t in c.fill_target_leaders:
                        if t.instance == i.id and t.name == c.name:
                            raise ValueError(
                                f"Character {c.name}: fill target 不能指向自己")
                        target = by_key.get((t.instance, t.name))
                        if target is None:
                            raise ValueError(
                                f"Character {c.name}: fill target ({t.instance}, {t.name}) 不存在")
                        if target.role not in (RoleEnum.LEADER, RoleEnum.EITHER):
                            raise ValueError(
                                f"Character {c.name}: fill target {t.name} 不是 leader/either")
        return self
```

**这就是原来 `RootConfig._cross_checks` 的原文，逐字搬运**——只把 `self.instances`
的语义从「全部实例」变成「本模式的实例」，文案与条件一个都不许改。搬完把 `RootConfig`
上原来的 `_cross_checks` 整个删掉（别留成死代码）。

- [ ] **Step 5: 重排 `RootConfig`，加老格式报错与 `instances_for`**

把 `RootConfig` 换成：

```python
class RootConfig(BaseModel):
    app: AppConfig = Field(default_factory=AppConfig)
    zhaiduo: ZhaiduoConfig
    gem: ModeConfig = Field(default_factory=ModeConfig)
    quiz: ModeConfig = Field(default_factory=ModeConfig)

    @model_validator(mode="before")
    @classmethod
    def _reject_legacy_flat_instances(cls, data):
        """老格式（顶层 instances）→ 可操作的报错。

        pydantic 默认忽略多余键，直接后果是用户看到一句光秃秃的
        `zhaiduo / Field required`，不知道该干什么。**这是报错，不是迁移**：
        经确认不做自动迁移，老配置报错、用户重配。

        必须放在 RootConfig 的 mode="before" 里，不能挂在 load_config() 上——
        GuiController.load_config 自己走 model_validate，不经过 load_config()。
        """
        if isinstance(data, dict) and "instances" in data and "zhaiduo" not in data:
            raise ValueError(
                "配置格式已更新：instances 现在挂在 zhaiduo 模式下。"
                "请删除 config.yaml 后重启，程序会从 config.example.yaml 重新生成一份。")
        return data

    def instances_for(self, mode: AppMode) -> list[InstanceConfig]:
        """该模式的实例列表。模式 → 配置段的映射只有这一处。"""
        return getattr(self, mode.value).instances
```

        """左侧模式导航 + 右侧模式页栈（spec §5.3）。"""

        self.mode_nav.setObjectName("modeNav")

        for mode in AppMode:
            item = QListWidgetItem(MODE_LABELS[mode])
            item.setData(Qt.ItemDataRole.UserRole, mode)
            self.mode_nav.addItem(item)
        self.mode_nav.currentRowChanged.connect(self._on_mode_changed)
        self.mode_nav.setCurrentRow(0)   # Qt 默认 -1 = 三项都没高亮，界面看着像没选中

        for mode in AppMode:

            # lambda 默认参数捕获 mode：否则所有页面共用循环结束时的那个值
            page.start_btn.clicked.connect(lambda _=False, m=mode: self._on_start(m))
            page.stop_btn.clicked.connect(self._on_stop)
            self._pages[mode] = page
            self.mode_stack.addWidget(page)

            self.mode_stack.setCurrentIndex(row)

    def _sync_ui_state(self):
        """从三个输入推导全部界面状态：运行中的模式 / 本页的模式 / 有无角色。

        互斥不是靠三处 if 维护的，是从 _running_mode 这一个状态**推导**出来的
        （spec §5.4）。加模式维度后散落的 setEnabled 会翻倍，改一处漏一处。
        """
        running = self._running_mode is not None
        self.mode_nav.setEnabled(not running)          # 运行中锁导航
        for mode, page in self._pages.items():
            page.start_btn.setEnabled(not running and page.implemented)
            page.stop_btn.setEnabled(running and mode == self._running_mode)
            if not page.implemented:
                page.body.setCurrentIndex(ModePage.LOCKED)
            elif self._cards:
                page.body.setCurrentIndex(ModePage.CARD)
            else:
                page.body.setCurrentIndex(ModePage.EMPTY)
