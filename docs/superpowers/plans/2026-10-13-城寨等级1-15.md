# 城寨等级 1–15 —— 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让搜索目标等级从 1–10 扩到 1–15，并把「1–10 / 11–15 是两个互斥区间」这件事在配置校验、状态机、配置界面三处都表达出来。

**Architecture:** 「等级区间」提升为一等概念（`level_range(lv) -> (low, high)`），因为它在三处出现：校验判定「混选了两个区间」、状态机决定点哪个区间控件、盲降决定降到底的落点与次数。状态机沿用仓库既有的**灰态模板 + 幂等点击**惯用法切区间（与 `tab_fortress` / `tab_raider` 同一套），不需要先读「当前在哪个区间」。跨区间会让既有的等级缓存失步，一并修掉。

**Tech Stack:** Python 3 / pytest / pydantic v2 / PyQt6 / OpenCV 模板匹配（`TM_CCOEFF_NORMED`）。

**Spec:** `docs/superpowers/specs/2026-10-13-多模式框架与城寨等级扩展-design.md`（本计划只实现 §4；§5 的多模式框架是 B 部分，本计划不碰）

```python
#
# 注意别和上面那个 MAX_TARGET_LEVELS 看串了：**S 结尾的是「最多勾几个」
# （=3），不带 S 的是「最大是几级」（=15）**。两个名字只差一个字母，改这两
# 块代码时先确认自己在改哪一个。
#
# 面板上 1–10 与 11–15 是**两个互斥的区间**，由一个独立的区间控件切换，
# 不是一根连续滑条。所以「同一次搜索里混选两个区间」没有意义：面板同一
# 时刻只能停在其中一个区间上，另一个区间里的等级根本搜不到。
MIN_TARGET_LEVEL = 1
MAX_TARGET_LEVEL = 15
RANGE_BOUNDARY = 10          # 1..10 | 11..15 的分界


def level_range(lv: int) -> tuple[int, int]:
    """该等级所属区间的 (下界, 上界)：1–10 → (1, 10)；11–15 → (11, 15)。

    区间在本次改动里同时出现在三处（校验互斥、切面板区间、盲降降到底），
    所以给它一个名字，而不是在三处各写一遍 `if lv > 10`。
    """
    if lv <= RANGE_BOUNDARY:
        return (MIN_TARGET_LEVEL, RANGE_BOUNDARY)
    return (RANGE_BOUNDARY + 1, MAX_TARGET_LEVEL)
```

```python
    def _switch_level_range(self, target: int) -> None:
        """把搜索面板切到 target 所在的等级区间（灰态模板，幂等）。

        与 tab_fortress / tab_raider 同一套惯用法：模板只裁**未选中**态，
        命中 ⇔ 当前不在该区间 ⇔ 点它；已在目标区间就不命中，`_click`
        自动跳过。**不需要先读状态**——「面板当前停在哪个区间」本来就不
        容易读准，靠"点一下没坏处"把这个不确定性消掉。
        """
        low = level_range(target)[0]
        rid = "level_range_high" if low > RANGE_BOUNDARY else "level_range_low"
        if rid not in self._rec:
            if low > RANGE_BOUNDARY:
                # 识别器缺失时 `_click` 是**静默空操作**。对 11–15 目标不能
                # 静默：点不动区间控件就会在 1–10 区间里搜，等于「配置要 13、
                # 实际搜 8」。宁可按异常结束本轮（runner 会计失败并停机）。
                raise RuntimeError(
                    f"目标等级 {target} 属于 {low}–{MAX_TARGET_LEVEL} 区间，"
                    f"但识别器里没有 {rid}"
                    "（templates/manifest.yaml 缺条目或模板 PNG 缺失）")
            # 低区间：旧模板包没有这个条目，行为与改动前一致（只警告）。
            # 若面板实际停在 11–15 区间会搜错等级，但**不静默**——回读值
            # 不在目标区间内会被 _verify_level 判失败并留下 warning，
            # 最终由 no_result 计数自然兜住本轮。
            logger.warning(
                "[车头] 缺少 %s 识别器，无法确认面板停在哪个等级区间；"
                "若面板停在 %s–%s 区间会搜错等级", rid,
                RANGE_BOUNDARY + 1, MAX_TARGET_LEVEL)
            return
        self._click(rid)
```
